# トレーサビリティ確認

成果物の各要素が、入力（要件や前工程の成果物）のどこから来ているかを確かめる。

---

## 目的

- 入力にない要素が紛れ込むのを防ぐ（AIが要件を補って書くことを防ぐ）
- 入力の要素の取りこぼしを防ぐ
- 後で変更があったとき、影響する範囲を辿れるようにする

---

## 手順

1. **入力の要素を列挙する**：入力の成果物から、このフェーズで扱うべき要素を洗い出す（例：1-1 なら要件の機能要件と業務ルール）
2. **順方向に確かめる**：入力の各要素が、成果物のどこかで扱われているか確かめる。扱わない要素には理由を書く
3. **逆方向に確かめる**：成果物の各要素が、入力のどれかに根拠を持つか確かめる。根拠のない要素は削るか、確認待ちにする
4. **抽出元を書く**：スキルの出力フォーマットに「抽出元」の欄がある場合は、入力の要素の番号や ID を書く

---

## 抽出元の書き方

| 入力 | 書き方 | 例 |
|---|---|---|
| 要件 | 要件の節と項目の番号 | 要件 4-1-2、業務ルール 3 |
| 前工程の成果物 | ID と記法のルールに従った ID | UC-03、Concept:注文、E:在庫 |

---

## よくある問題

- 要件に「〜できる」とあるだけの機能に、書かれていない手順や条件を補ってしまう
- 「参考」「要望」として書かれたものを、要件として扱ってしまう
- 対象外に書かれたものを成果物に含めてしまう
