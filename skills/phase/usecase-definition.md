# ユースケース定義

---

## 1. 目的

- シナリオの範囲を決める
- シナリオの目的を決める
- アクターとトリガーを明らかにする
- 外から見える振る舞い（主シナリオ／代替シナリオ）を列挙する
- 開始前と終了後の状態（事前条件・事後条件）を宣言する

---

## 2. 必要な情報

- 要件（機能要件、業務ルール、利用者、対象外）

---

## 3. 手順

1. 要件の利用者と機能要件から、ユースケースの候補を洗い出す
2. ユースケース一覧を作り、各ユースケースに ID を振る（ID は id-notation に従う）
3. ユースケースごとに、出力フォーマットの項目を埋める
4. 業務ルールを、どのユースケースの事前条件・事後条件・代替シナリオに反映するかを決める
5. 事前条件と事後条件は自然言語で書く（Entity 単位の展開は 1-3 で行う）
6. traceability-check に従い、要件の機能要件と業務ルールがすべてどこかのユースケースで扱われているか確かめる
7. 完了条件を確かめる

---

## 4. 出力フォーマット

### ユースケース一覧

```markdown
## ユースケース一覧

| ID | 名称 | アクター | 抽出元 |
| --- | --- | --- | --- |
| UC-01 | ［ユースケース名］ | ［アクター］ | ［要件の番号］ |
```

### ユースケースごと

```markdown
## ユースケース：［名称］

| 項目 | 内容 |
| --- | --- |
| ユースケースID | UC-XX |
| 名称 | ［ユースケース名］ |
| アクター | ［誰が操作するか］ |
| 目的 | ［このユースケースが達成したい目的］ |
| 概要 | ［外から見た流れの一文］ |
| トリガー | ［開始条件：画面操作 or APIなど］ |
| 事前条件 | ［開始時に満たされている状態］ |
| 事後条件 | ［終了時に保証される状態］ |
| 抽出元 | ［要件の番号］ |

### 主シナリオ
1. ［アクター or システム：動作］
2. ［アクター or システム：動作］
3. ［…］

### 代替シナリオ
- ［エラー条件 → システムの振る舞い］
```

---

## 5. 品質評価基準

### OKの基準（すべて満たすこと）

| 基準ID | 基準 |
|---|---|
| UD-01 | アクターが具体的に書かれている（「ユーザー」だけでなく誰かが分かる） |
| UD-02 | 目的が「〜できる」「〜する」という動詞で表現されている |
| UD-03 | 事前条件が状態として書かれている（「〜している」「〜が存在する」など） |
| UD-04 | 事後条件が状態変化として書かれている（「〜が登録された」「〜が更新された」など） |
| UD-05 | 主シナリオが3ステップ以上あり、アクターとシステムのどちらの動作かが分かる |
| UD-06 | 代替シナリオ（エラー・例外）が1つ以上ある |

### よくある不十分パターン

- 事後条件が「処理が完了する」など曖昧な表現になっている（UD-04）
- 主シナリオがシステム側の動作しか書かれておらず、アクターの操作が抜けている（UD-05）
- 代替シナリオが「エラーを表示する」だけで、どのエラー条件かが書かれていない（UD-06）

---

## 6. 完了条件

- 要件の機能要件と業務ルールが、すべてどこかのユースケースで扱われている。扱わないものは理由が書かれている
- すべてのユースケースが品質評価基準 UD-01〜UD-06 を満たしている
- 確認待ちにした事項があれば、STATE.md に書かれ、成果物の該当箇所に「確認待ち」と明記されている

---

## 7. AIに任せない判断の例

このフェーズでは、次のような場面で止まって人間に確認する。

| 場面 | 該当する領域 |
|---|---|
| 業務ルールが複数の読み方をでき、どちらを取るかで主シナリオや代替シナリオが変わる | 要件の解釈が割れる |
| 要件に書かれていない例外や分岐を、代替シナリオとして補いたくなった | 要件の解釈が割れる |
| 「参考」「要望」として書かれたものや、対象外に書かれたものをユースケースにしたくなった | スコープの追加・削除 |
| 要件にある機能を、ユースケースにしないほうがよいと判断した | スコープの追加・削除 |

人間に確認するときの聞き方の例：

- 「事後条件が要件から読み取れません。このユースケースが正常に終わったとき、何がどう変わりますか？」
- 「この分岐に入る条件が要件に書かれていません。どういうときに、この代替シナリオになりますか？」
