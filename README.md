# 設計フレームワーク

要件定義の後から実装の前までの設計を、AIが設計ループを回し、人間が承認する形で進めるための設計フレームワーク。

このファイルは人間向けの入口。AIが作業に使う内容は LOOP.md と skills/ にある。

---

## 目的

要件から実装へつなげるために、「構造」「振る舞い」「品質」「工数」「クラス設計」を段階的に整える。

### やること

- ユースケースで振る舞い（外から見た動き）を固める
- 概念モデルで扱うデータ構造の範囲を定義する
- シナリオの各ステップを入出力／制御ロジック／データモデルに分類し、責務を明確にする
- 品質リスク（性能・整合性・外部依存など）を早めに拾う
- 入出力／制御ロジック／データモデルの数をもとに工数の見通しを立てる
- 制御ロジック・データモデル・入出力を実装できる粒度で設計する
- 後工程の人が迷わないように、必要十分な構造を文書にする

### やらないこと

- 性能検証・負荷試験の数値取得
- 画面デザイン・インフラ設計
- 要件そのものの再定義（要件に欠落や矛盾があれば、要件定義に戻す）

---

## 全体の流れ

```
要件
↓
【1. 概念設計】
  ├ 1-1. ユースケース定義      ★承認ポイント
  ├ 1-2. 概念モデリング
  └ 1-3. 責務割り当て          ★承認ポイント
↓
【2. 品質リスク分析】
↓
【3. 見積もり】                ★承認ポイント
↓
【4. 論理設計】
  ├ 4-1. 制御ロジック設計
  ├ 4-2. データモデル設計
  ├ 4-3. テーブル設計
  └ 4-4. 入出力設計
↓
【5. 例外フロー設計】          ★承認ポイント
↓
実装
```

★は常設の承認ポイント。立ち上げ直後（自律度 L1）は、すべてのフェーズの後で人間が承認する。

---

## 役割

| 役 | 担当 | やること |
|---|---|---|
| 実装者 | AI | スキルに従って各フェーズの成果物を作る |
| 検証役 | AI（実装者とは別の文脈） | 成果物を品質評価基準で検証し、承認か却下かを判定する |
| 人間 | 設計者 | フェーズを起動し、承認ポイントで承認または差し戻しを判断する |

---

## 使い方（人間向け）

初めて使うときは、SETUP.md に従って Claude Code に入れる。

1. 案件フォルダを作り、要件を `requirements.md` という名前で置く
2. 案件フォルダで Claude Code を起動し、`/design-loop 1-1` と打つ
   - `design/`（STATE.md、DECISIONS.md、reviews/）がなければ、実装者が作る
3. 実装者が成果物を作り、検証役が検証する。却下されれば実装者が直して再検証する（ここまで自動）
4. 実装者が止まったら、成果物と検証レポート（`design/reviews/`）を確認し、承認するか差し戻すかを決める
5. 承認したら、次のフェーズを `/design-loop 1-2` のように起動する

承認ポイントでは、成果物の要点を自分の言葉で説明できるかを確かめる。説明できなければ承認しない。

### `/design-loop` でループが回るしくみ

`/design-loop` は、Claude Code のスラッシュコマンド（スキル）。`install.sh` が `entry/design-loop.md` を `~/.claude/skills/design-loop/SKILL.md` にコピーすることで使えるようになる。

`/design-loop 1-1` と打つと、**いま開いている Claude Code のセッションそのものが実装者になる**。ループは次の2重になっている。

```
人間：/design-loop <フェーズ番号>
↓
【内側のループ】1回の /design-loop の中で自動で回る
  実装者（いまのセッション）：スキルに従って成果物を作る
  ↓
  検証役（サブエージェント design-verifier）：別の文脈で成果物を検証する
  ↓
  却下 → 実装者が直して、もう一度検証役に回す（上限3回。同じ基準IDの必須が2回、または DL の指摘が出たらすぐ止まる）
  承認 → 内側のループを抜ける
↓
実装者が止まる（STATE.md のフェーズが「承認待ち」になる）
↓
【外側のループ】人間が回す
  人間：成果物と検証レポートを確認し、承認するか差し戻すかを決める
  ↓
  人間：次のフェーズを /design-loop <次の番号> で起動する
```

- 内側のループは、人間が何もしなくても回る。止まるのは、検証役が承認したとき、繰り返し上限に達したとき、AIに任せない領域に当たったとき（LOOP.md の「停止条件」）
- 外側のループは自動では回らない。次のフェーズに進むのは、人間が `/design-loop` を打ったときだけ
- 進み具合は `design/STATE.md` に残る。セッションを閉じても、新しいセッションで `/design-loop` を打てば続きから再開できる
- フェーズ番号を付けずに `/design-loop` だけを打つと、実装者が STATE.md を見て次に進むべきフェーズを示し、確認してから始める

## フォルダ構成

| 場所 | 内容 |
|---|---|
| README.md | このファイル |
| LOOP.md | ループの流れ・承認ポイント・停止条件（AIが最初に読む） |
| roles/ | 実装者と検証役の振る舞い |
| skills/phase/ | フェーズごとのスキル |
| skills/common/ | どのフェーズでも使う共通スキル（用語、ID と記法など） |
| templates/ | 案件で使うファイルのひな形 |
| indicators/ | 設計の指標の案（スキルへの組み込み前）。インストールの対象外 |
| entry/ | `/design-loop` コマンドの原本。インストールでスキルとして登録される（「`/design-loop` でループが回るしくみ」を参照） |
| install.sh、SETUP.md | Claude Code に入れるためのスクリプトと手順 |

用語の定義は `skills/common/glossary.md` を参照。
