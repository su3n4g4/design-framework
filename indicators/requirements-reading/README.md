---

- A：新しいフェーズ「0 要件の読み合わせ」を足す（LOOP.md のフェーズ一覧・フェーズ規律・STATE.md のひな形が変わる）

## 共通の決まり

- 読み合わせは問うだけにする。答えを AI が決めない（DL-01）
- 1つの条文に、当てはまる指標が複数あってよい
- 「要件から読める」とするときは、根拠の箇所を書く
- 後のフェーズに送る問いには、送ってもユースケースの流れが変わらない理由を書く（RG-06 の D-012 → D-061 の再発防止）

## ファイルの形

1指標＝1ファイル。frontmatter の項目は次のとおり。RAG のチャンクとメタデータにそのまま使う。

| 項目 | 中身 |
|---|---|
| id | 基準ID |
| name | 観点 |
| group | 指標のまとまり（要件の読み合わせ） |
| judge | 判断／機械（機械で判定できるものはスクリプトで確かめる） |
| status | 案／採用 |
| related | 関係する基準ID |
| pilot | pilot での件数（全体、1-1で、1-1より後、差し戻し） |

本文の「当てはまる要件の書き方」が検索のきっかけになり、「OK例・NG例」が過去の実例になる。

---

## 評価のときの注意

OK例・NG例は pilot から取った。pilot で効果を測るときは、指標の本文から例を外したもので読み合わせを回し、1-1 より後で出た41件のうち何件を先に拾えるかを数える。例を入れたままだと答えを見ながら解くことになる。本当の効果は2件目の案件で測る。
